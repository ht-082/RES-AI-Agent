# 파일명·폴더구조 규칙 (재적재 전 정리 기준)

> 작성 2026-08-10 · 대상: `backend/media/initial_docs` 488건
> **이 작업은 재적재 전에 끝내야 한다.** 이유는 §0.

## 0. 왜 지금, 왜 이 규칙인가

| 이유 | 내용 |
|---|---|
| **파일명이 검색에 들어간다** | 임베딩 입력 앞에 `[사업: 당진행복솔라] [문서: 대주별 선순위 인출금액]` 헤더가 붙는다. 헤더 상한 60자에서 사업명 몫을 빼면 **문서명 예산은 약 38자**. 초과분은 뒤에서 잘린다 (현재 14%가 잘림) |
| **파일 경로가 청크 ID의 씨앗이다** | 적재 후에 이름·폴더를 바꾸면 그 문서 청크 ID가 전부 새로 발급된다 → 과거 대화의 출처가 끊긴다. **지금 하면 공짜, 나중에 하면 재적재** |
| **최신본 판별을 코드로 해야 한다** | 지금 버전 표기가 11종 난립(날인본13·수정12·최종11·사본11·clean10·서명본9·(1)9·v숫자6·Final6·★4·Rev3). 규칙이 있어야 "같은 문서의 옛 버전은 검색에서 제외"를 자동화할 수 있다 |

**파일 내용은 건드리지 않는다.** 이름만 바꾸는 건 checksum이 그대로라 중복 적재 방지 로직에 영향이 없다.

## 1. 기본 규칙

```
문서종류_대상_YYMMDD[_v번호][_날인].확장자
```

| 순서 | 슬롯 | 필수 | 설명 |
|---|---|---|---|
| 1 | **문서종류** | ✅ | 계약서 · 과업지시서 · 보고서 · 허가증 · 공문 · 시방서 · 요청서 · 합의서 · 명세서 |
| 2 | **대상** | 권장 | 같은 종류를 구분하는 말. `EPC` `부지확보` `대민대관` `개발행위허가` `1회차` `염도평가` |
| 3 | **YYMMDD** | 권장 | 6자리. 없으면 생략 |
| 4 | **v번호** | 선택 | `v2` `v3`. **숫자가 클수록 최신** |
| 5 | **날인/초안** | 선택 | `_날인`(서명·날인 완료본), `_초안`. 이 둘만 허용 |

**전체 38자 이내를 권장한다** (헤더 예산). 넘으면 대상 슬롯을 줄인다.

### 슬롯 순서가 이 순서인 이유

헤더는 **뒤에서 잘린다.** 문서종류가 앞에 있어야 잘려도 "무슨 문서인지"는 살아남는다. 날짜를 앞에 두면 정렬은 편하지만 잘렸을 때 아무 정보도 안 남는다 — 시간순 정렬은 탐색기의 '수정한 날짜'로 대신한다.

## 2. 금지 목록

| 금지 | 현재 | 대신 |
|---|---|---|
| **공백** | 423/488건 (87%) | `_` |
| 최종 · Final · clean · 수정 · 사본 · Rev | 11종 난립 | **`v번호`로 통일** |
| 서명본 · 날인본 | 22건 | `_날인` |
| `(1)` `(2)` 형태 | 9건 | `v2` `v3` |
| `★` | 4건 | 삭제 |

| **사업명** | 다수 | **삭제** — 폴더가 사업이고 헤더가 자동으로 붙인다. 넣으면 38자 예산만 먹는다 |
| 담당자명 | 일부 | 삭제 (`정혁태M` 등) |

**날짜는 YYMMDD 6자리로 통일.** 현재 4형식 혼용(YYMMDD 92 · YYYYMMDD 36 · YY.MM.DD 13 · YY-MM-DD 2).

**영문 약어는 대문자 유지**: `EPC` `PF` `SPA` `SHA` `O&M`→`OM` `REC` `SMP` `FM`(재무모델) `OE`

## 5. 폴더 구조

```
initial_docs/
├─ 00_공통/                  법령·고시·표준양식 (사업 무관)
└─ NN_사업명/
    ├─ 01_사업개요/          사업개요 · 현황 · 요약
    ├─ 02_인허가/            발전사업허가 · 개발행위허가 · 환경영향평가 · 송전용전기설비이용계약
    ├─ 03_부지_주민/         토지 매매·임대차 · 지역수용성 · 주민참여 · 염도측정
    ├─ 04_금융/              대출약정 · 자금인출 · 펀드 · 자금집행 · 재무모델
    ├─ 05_지분/              SPA · SHA · 주주협약 · 출자
    ├─ 06_EPC_기술/          EPC 계약 · 기술규격서 · 시방서 · 설계 · 입찰
    ├─ 07_운영/              OM · 관리운영위탁 · 보험 · 정산
    └─ 08_보고_실사/         경과보고 · 감리보고 · 회의록 · 실사 · 경제성
```

**최상위 폴더명은 사업명 그대로.** 그래야 헤더에 그 이름이 그대로 들어간다.

```
00_공통 / 01_당진행복솔라 / 02_당진대호솔라 / 03_홍성 / 04_태평염전 / 05_임자도 / 06_안면도
```

### 규칙

- **번호는 사업 진행 순서다. 쓰는 폴더만 만든다.** 빈 폴더를 만들지 않는다 — 현재 태평은 5칸 중 4칸이 0건, 홍성도 3칸이 0건이다
- **깊이는 최대 3단계** (사업/단계/반복단위). 3단계는 회차·업체처럼 반복되는 단위일 때만
- 편·장·절 같은 문서 내부 구조는 폴더가 아니라 파일명으로 (현재 EPC 기술규격서가 7단계)
- 최상위에 파일을 바로 두지 않는다 (현재 홍성1·임자4·안면도1·태평1건)

### 현재 → 신규 매핑

| 현재 | 신규 |
|---|---|
| 홍성 `발전사업허가` `개발행위허가` `송전용전기설비이용계약` | `02_인허가` |
| 홍성 `염도 측정 결과서` `지역수용성` | `03_부지_주민` |
| 홍성 `펀드` | `04_금융` |
| `Contract` (당진1 84건 등) | **성격별 분해** → 04(대출약정)·05(SPA/SHA)·06(EPC)·07(관리운영위탁) |
| `Financial/10. 자금인출/N회차 인출` | `04_금융/인출_N회차` |
| `Contract/09. EPC/…/제Ⅳ편/제N장/제N절` | `06_EPC_기술/기술규격서` + 편·장은 파일명으로 |
| `Permission` | `02_인허가` |
| 임자·안면도 `01_보고자료` `03_실사` `04_경제성` | `08_보고_실사` |
| 임자 `00_현황` | `01_사업개요` |
| `General` `Report` | 내용 보고 배분 |

## 6. 이름과 별개로 조치가 필요한 31건

파서가 못 읽는 형식이다. 이름을 바꿔도 인덱싱이 안 된다.

| 형식 | 건수 | 조치 |
|---|---|---|
| `.zip` | 13 | **압축 해제 필요.** 임자·안면도·태평 "계약서.zip"(16.8/22.2/4.4MB)에 계약서가 통째로 들어있다 — 안 풀면 세 사업 계약서가 통으로 빠진다 |
| `.xlsm` | 8 | 파서 한 줄 수정으로 지원 가능 (재무모델 파일들) |
| `.msg` | 6 | 미지원 (아웃룩 메일) — 필요하면 본문을 pdf로 |
| `.doc` | 4 | 미지원 (구 워드) — docx로 변환 |
