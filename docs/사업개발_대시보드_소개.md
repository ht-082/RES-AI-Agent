# 사업개발 대시보드 — 소개

> RES AI Agent 안의 **사업 관리 화면**. 태양광 발전사업 6개(홍성1 · 당진1 · 당진대호솔라 ·
> 임자도 · 안면도 · 태평염전)의 인허가·계약·예산·경제성을 한 곳에서 보고 고친다.
>
> 들어가는 길: 왼쪽 메뉴 **사업 관리 Dashboard**

원래 별도 서비스(Re-project-mng, 정적 HTML + Supabase)로 있던 대시보드를 이 프로젝트의
기술 스택(Django + DRF + React)으로 옮겨 하나로 합친 것이다. Supabase 프로젝트가 소멸해
원본은 더 이상 실행되지 않는다.

---

## 1. 화면 두 장

### 전체 사업 화면

| 구역 | 내용 |
|---|---|
| KPI 4장 | 전체 등록 사업 · 개발 중 파이프라인 · 금월 Pending 이슈 · 금월 법령 동향 |
| 포트폴리오 지도 | 사업지 핀(태양광 주황 / 풍력 청록). 클릭하면 요약 카드 → 상세로 이동 |
| 계통 접속 가능용량 | 시·도별 포화율(KEPCO 스냅샷) |
| 영향 법령 동향 | 최근 법령 3건(법제처 스냅샷) |
| **사업 List** | **개발 중 / 운영 중으로 나눠** 7단계 인허가 진척을 점으로 표시 |

사업을 누르면 **개발 사업은 개발 상세로, 운영 사업은 운영 상세로** 갈라져 들어간다.
보아야 할 것이 다르기 때문이다 — 개발은 인허가 진척, 운영은 발전 실적.

### 사업 상세 화면 (개발)

사내 **사업개요 문서 양식**을 그대로 화면으로 옮겼다. 박스 하나가 문서의 한 절이다.

```
사업 개요 + 지도          │  SPC 정보 (지분구조도)
                         │  부지 정보
─────────────────────────┼──────────────────────
예산 승인 · 집행           │  계약 정보
경제성 및 총사업비          │  진행경과 및 이슈
──────────────────────────────────────────────
인허가 현황  (상·하위 묶음 카드)
금융(PF)
계통 상황                 │  조례 모니터링
```

읽는 화면에는 표를 쓰지 않는다 — 타임라인·목록 카드·숫자 타일로 그리고,
**표는 편집 팝업 안에서만** 쓴다. 격자선이 시선을 잘라 읽기를 방해하기 때문이다.

## 2. 특징적인 부분

**인허가 현황** — 상위 절차와 그에 딸린 협의를 들여쓰기로 묶는다. 개별법 협의 7건
(환경영향평가 · 재해영향평가 · 농지 2건 · 경관심의 · 교통계획 · 문화재지표조사)은
개발행위허가 아래에 붙는다. 묶음은 `tier`(상위/하위) + 줄 순서로 정해지므로,
편집 팝업에서 ▲▼로 옮기거나 상위/하위를 바꾸면 계층이 따라 바뀐다.

본문은 자유 입력이 아니라 **채울 칸이 정해져 있다.**

| 항목 | 채울 칸 |
|---|---|
| 발전사업허가 | 허가번호 · 용량 · 허가일자 · 허가조건 |
| 송전용전기설비이용계약 | 계약전력 · 이용개시일 |
| 개발행위허가 | 면적 · 필지수 |
| 환경영향평가 | 대상 유형 |

문서 버전 관리가 붙어 있다 — 허가증을 올리면 v1, v2로 쌓이고 이력에서 예전 버전을
다시 최신으로 지정할 수 있다.

**경제성 및 총사업비** — 금융모델(Time Line & Assumption / 총투자비)의 구성을 옮겼다.
수익률(E.IRR · P.IRR)을 맨 위에 크게 두고, 가정사항 → 사업비 → 손익 순으로 읽는다.
총사업비·총투자비는 **구성 항목에서 서버가 더한다**(사람이 따로 입력하지 않는다).

**같은 수치를 두 곳에 두지 않는다.** 총사업비·총투자비 합계, 공사기간(개월),
운영종료일, 차입금 비율, MW당 단가, 대시보드 진척률은 모두 계산값이다. 값을 두 군데
저장하면 반드시 어긋난다.

## 3. 데이터는 어디에 있나

RAG 챗봇과 **같은 PostgreSQL**(`re_agent` DB)의 `bizdev_*` 테이블 9개.

| 테이블 | 담는 것 |
|---|---|
| `bizdev_sites` | 사업지(이름 · 용량 · 위치 · 단계 · 좌표) |
| `bizdev_site_facts` | 사업개요 양식의 각 줄(구분·내용·확정도) — 사업당 62줄 |
| `bizdev_permit_stages` / `_permit_documents` | 인허가 항목과 첨부 문서(버전별) |
| `bizdev_contracts` · `bizdev_site_events` | 계약 정보 · 진행경과 및 이슈 |
| `bizdev_budget_approvals` / `_entries` | 승인 예산 · 집행 실적(증빙 첨부) |

현재 담긴 것: 사업 6 · 항목 372 · 인허가 97 · 계약 63 · 경과 52.

항목 구성(어떤 칸이 있는지)은 `backend/apps/bizdev/constants.py` 한 곳이 소유한다.
칸을 늘리려면 이 파일만 고치면 사업지 생성·시드·화면이 모두 따라온다.

### 문서로 등록하기

사업개요 md 문서를 읽어 사업지를 만드는 명령이 있다. 손으로 옮기면 오타가 난다.

```bash
docker compose exec backend python manage.py import_overview_md --dry-run   # 미리보기
docker compose exec backend python manage.py import_overview_md             # 등록
```

이미 있는 사업지는 건드리지 않는다. 덮어쓰려면 `--only <이름> --force` 로 대상을
분명히 지정해야 한다 — 문서에 없는 화면 편집분이 날아가기 때문이다.

## 4. 고칠 때

모든 값은 **로그인한 직원이면 누구나** 고칠 수 있다. 박스마다 있는
**「상세내용 확인 및 편집」** 버튼을 누르면 팝업이 열리고, 팝업 안에서 고친 값은
입력이 멎고 0.8초 뒤 자동 저장된다(따로 저장 버튼이 없다).

박스마다 **최종 편집일**이 머리에 표시된다.

## 5. 아직 안 된 것

- **운영 사업 상세 화면** — 발전 실적 중심으로 새로 만들 예정
- **인허가 나머지 항목의 채울 칸** — 공사계획인가 · 사용전검사 등은 아직 자유 입력
- **정확한 사업지 좌표** — 지오코딩(주소→좌표) API 연결 전이라, 홍성을 뺀 5개는
  시·군 중심에 점선 핀으로 임시 표시된다
- **계통·법령 실시간 연동** — 지금은 스냅샷 JSON. KEPCO·법제처 API 키가 붙으면 교체
- **사업개요 md 내보내기** — 화면 내용을 문서로 되돌려 RAG 색인에 넣는 흐름
