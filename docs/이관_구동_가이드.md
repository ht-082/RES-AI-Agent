# RES AI Agent — 이관·구동 가이드 (코퍼스 이식 방식)

> 대상: 이 저장소를 넘겨받아 자기 PC/서버에서 구동하려는 개발자.
> 원본 문서 없이 **적재 완료된 코퍼스(스냅샷+덤프)를 이식**받아 RAG를 바로 돌리는 절차다.
> 원본 문서로 처음부터 적재하려면 이 문서 대신 `README.md`의 설치 4단계를 따르면 된다.

## 0. 받아야 하는 것

| 경로 | 내용 |
|---|---|
| GitHub | 코드 전체 (`git clone https://github.com/ht-082/RES-AI-Agent.git`) |
| 별도 전달 (zip) | `corpus_package/` — Qdrant 스냅샷(약 157MB) + PG 데이터 덤프(약 45MB) + 복원 스크립트 |
| 각자 준비 | OpenAI API 키 (gpt-5.6 계열 사용 가능한 키), Docker Desktop, 디스크 여유 약 10GB |

zip에는 사내 문서의 **본문 청크가 그대로** 들어 있다. 사내 자료와 동일한 보안 등급으로 다뤄야 한다.

## 1. 클론 + 환경변수

```bash
git clone https://github.com/ht-082/RES-AI-Agent.git
cd RES-AI-Agent
cp .env.example .env                    # docker-compose 용 (DB 계정)
cp backend/.env.example backend/.env    # Django 용 (API 키 등)
```

`backend/.env`에서 반드시 채울 것:
- `DJANGO_SECRET_KEY` — 비면 기동 자체가 중단된다. 생성:
  `python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"`
- `LLM_API_KEY` — 본인 OpenAI 키
- `LLM_MODEL` / `LLM_VISION_MODEL` — 기본 `gpt-5.6-terra` 유지 권장
  (gpt-5.x는 추론 모델이라 `temperature=0` 미지원·`max_completion_tokens` 사용.
   코드가 이에 맞춰져 있으므로 4o 계열로 내리려면 `services/vision_parser.py`와
   `apps/rag/.../ingest_initial_docs.py`의 파라미터를 확인해야 한다)
- 루트 `.env`와 `backend/.env` 양쪽의 `LLM_API_BASE`/`LLM_API_KEY`는 같은 값으로.

## 2. 기동

```bash
docker compose up -d
```

첫 기동 시 BGE-M3 임베딩 모델(~2GB)을 HuggingFace에서 받는다 — 인터넷 필요.
사내망 SSL 문제가 나면 README의 "개발 메모" 섹션 참고.

컨테이너 6개(`re_backend/frontend/postgres/qdrant/redis/worker`)가 뜨면 정상.
이 시점의 DB는 스키마만 있고 비어 있다.

## 3. 코퍼스 이식

전달받은 `corpus_package/`를 프로젝트 루트에 풀고:

```bash
# 3-1. PG 데이터 (프로젝트·문서 메타·청크 본문). 순서 내장된 스크립트라 그대로 실행
docker exec -i re_postgres psql -U re_user -d re_agent < corpus_package/corpus_data.sql

# 3-2. Qdrant 스냅샷 (벡터 18,823개)
curl -X POST 'http://localhost:6333/collections/re_documents_v2/snapshots/upload?priority=snapshot' \
  -F 'snapshot=@corpus_package/re_documents_v2.snapshot'
```

두 파일은 **같은 시점의 쌍**이다. 한쪽만 다른 버전으로 갈면 청크 ID가 어긋나
"본문 없는 후보" 경고가 뜬다.

## 4. 검증

```bash
# 문서·청크 수 (기대값: indexed 399 · 청크 18,823)
docker exec re_postgres psql -U re_user -d re_agent -c \
  "select status, count(*) from documents group by status; select count(*) from document_chunks;"

# Qdrant 벡터 수 (기대값: 18823)
curl -s http://localhost:6333/collections/re_documents_v2 | grep -o '"points_count":[0-9]*'

# 검색 실사격
docker exec re_backend python -c "
import os, django; os.environ.setdefault('DJANGO_SETTINGS_MODULE','config.settings'); django.setup()
from services.retriever import retrieve_for_views
docs = retrieve_for_views('당진행복솔라 PF 대주단 구성')
print(len(docs), '건 · 1위:', docs[0].payload.get('document_title'))"
```

브라우저 `http://localhost:5173` → 로그인 계정은 생성 필요:
```bash
docker exec -it re_backend python manage.py createsuperuser
```

## 6. 이식 코퍼스의 알려진 한계

- **출처 칩의 "원문 열기"는 404** — 원본 파일(`media/documents/`)은 이관에 포함되지 않는다.
  검색·답변 품질에는 영향 없음. 원본이 필요해지면 별도 협의.
- DRM 걸린 4건(관리운영위탁 계약 2·EPC목적설계·당위성자료)은 원래부터 미적재.
- `약정서_대출_220531.pdf`(안면도 365p)는 보류 상태로 코퍼스에 없음.
- 사업개요 md 중 당진2·임자·안면도는 AI 초안(문서에 "원본 우선" 명시됨).

## 7. 문서 추가·갱신 (이관 후 운영)

새 문서는 `backend/media/initial_docs/{PJT폴더}/`에 넣고:
```bash
docker exec re_backend python manage.py refresh_doc --file "media/initial_docs/…"
```
결정적 청크 ID라 기존 코퍼스와 안전하게 합쳐진다. 상세는 README "자주 쓰는 명령".
