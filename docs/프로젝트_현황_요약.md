## 1. 무엇을 만들었나

재생에너지(태양광) 사업개발실의 **사내 문서 RAG 챗봇**. 6개 발전사업(홍성·당진1·당진2·임자·안면도·태평)의
계약서·허가증·보고서·재무모델 약 400건을 근거로 답하고, 참조한 원문 청크를 출처 칩으로 보여준다.
계약서 생성·재무모델 기능은 별도 개발자가 진행 중이며 이 저장소에 병합 예정 (`apps/contracts`, `frontend/features/finance` 뼈대 존재).

## 2. 기술 스택

| 층 | 구성 |
|---|---|
| 백엔드 | Django 5 + DRF, Python 3.12 — `:8000` |
| 프론트 | React 18 + TypeScript + Vite — `:5173` |
| 벡터DB | **Qdrant 1.18.1** — 하이브리드 검색(dense+sparse, Prefetch API), 컬렉션 `re_documents_v2` |
| RDB | PostgreSQL 16 — 청크 **본문**은 여기(document_chunks), Qdrant엔 벡터+메타만 |
| 임베딩 | **BGE-M3** (FlagEmbedding, 로컬 CPU) — dense+sparse 동시 생성 |
| 리랭커 | **bge-reranker-v2-m3** OpenVINO INT8 (로컬 CPU) — IR 재생성: `python bench_openvino.py c` |
| LLM | **gpt-5.6-terra** (OpenAI API) — 답변·문서분류·스캔본 OCR 전부 통일. 4o-mini는 한글 고유명사 오독으로 폐기 |
| 웹검색 | Tavily (사용자 토글 시에만) |
| 기타 | Redis+Celery(worker), Docker Compose 컨테이너 6개 |

## 3. 파이프라인

```
[적재] parse(fitz/hwp5html/docx/openpyxl, 스캔본→terra Vision OCR)
     → 문서분류(규칙·파일명 접두 우선, 폴백만 LLM)
     → 유형별 청킹(chunkers.py: 계약=조항, 법령=조문, md=헤딩, 표=행렬 보존)
     → normalize_chunks 단일 출구 + verify_chunk_invariants(치명 위반 시 문서 거부)
     → 임베딩 입력에 컨텍스트 헤더 '[사업: X] [문서: Y]' 주입 (md/txt 제외)
     → 결정적 청크ID(내용 기반 uuid5) → Qdrant(벡터+payload) + PG(본문)

[질의] Qdrant 하이브리드 top-16 → PG에서 본문 join → 완전중복 제거
     → 리랭킹(입력에 임베딩과 동일한 헤더 주입) → 게이트(top1≥0.55, margin 0.12)
     → 통과 0건이면 "관련 자료를 찾지 못했습니다" 고정응답 (LLM 미호출)
     → LLM(terra, 최근 대화 10개 + 청크 컨텍스트) → SSE 스트리밍 + 출처 칩
```

## 4. 현재 상태 (실측)

- **코퍼스 v2.0 활성**: 문서 399 indexed · 청크 18,823 · PG↔Qdrant 정합 일치. v1.0(10,777)은 롤백용 보존
- 청크 규격: 상한(1,500자) 초과 0 · 제어문자 0 · 초소형 3.1%
- 리랭커 파라미터(실측 재산정): `RAG_RETRIEVE_K=16`, `RERANK_MAX_LENGTH=384`, 게이트 0.55 — 384 vs 768 순위 동일·지연 2.4배라 유지

## 5. 핵심 설계 결정 (이유 포함 — 바꾸기 전에 읽을 것)

1. **본문은 PG, 벡터는 Qdrant** — payload에 content 없음. 스냅샷만 이관하면 RAG 안 돌아감(덤프와 쌍 필수)
2. **컨텍스트 헤더**: 폴더명→사업명 별칭표(`backend/project_aliases.json`)로 임베딩·리랭커 양쪽에 주입.
   실증: 문서명이 신호인 청크가 리랭킹 17위→1위. **폴더명 바꾸면 별칭표도 같이** 바꿔야 함(안 하면 조용히 품질 저하)
3. **결정적 청크ID**(collection:파일경로:정규화본문 uuid5) — 재적재·부분갱신에도 ID 안정, refresh_doc 안전
4. **청킹은 순수 규칙**(LLM 없음) — 재현성·결정성. 표 분할 시 제목 재부착은 상한 역산 후(광폭 표 9건 실패 교훈)
5. **사업개요 md는 헤더 주입 제외** — 대신 모든 헤딩에 사업명 필수(`## 5. 계약 정보 — 홍성1 태양광`). 인위적 가중치 없음(낡은 개요=확신에 찬 오답 방지)
6. **재무모델 xlsm**: 시트 화이트리스트(요약·가정·IRR만) + 주기접미사 `(Q)(Y)(FY)` 제외 + 12열 초과 표는 행 서술화 생략 — 안 하면 파일당 수천 청크
7. **검색은 마지막 질문 문장만 사용** (질의 재작성 보류) — 후속질문("어떤 업체야?")은 실패함.
   완화: UI에 "질문에 사업명 포함" 안내. 근본 해결책(재작성/명시우선+하드필터)은 설계만 완료
8. **모델은 terra 단일**: `LLM_MODEL`/`LLM_VISION_MODEL` env. UI 선택지는 terra/sol/luna(allowlist, 밖의 값은 서버 기본 폴백)

## 6. 함정 (다른 세션이 반드시 알아야 할 것)

- **gpt-5.x는 추론 모델**: `temperature=0` 거부, `max_tokens` 대신 `max_completion_tokens`. 코드가 이에 맞춰짐 — 4o 계열로 내리면 400 에러
- **Vision OCR은 페이지 단위 변환** — 전량 일괄은 365p 문서에서 OOM(실증). `VISION_OCR_MAX_PAGES=400`
- **OCR은 외부 전송**: 이미지가 OpenAI로 나감. `media/ocr_전송대장.csv`에 전량 기록(보안 감사용). 사내규정 적합성 판단 보류 중
- **`reset_db.py`류 전체 삭제 금지** — v1 롤백본까지 날아감 (해당 스크립트는 `_archive_초기개발/`로 격리됨)
- **적재 중 initial_docs의 오피스 파일 열지 말 것** — `~$` 잠금파일 생성(필터는 있음), 저장 시 checksum 변화로 중복 문서
- **audit_chunks는 v1+v2 합산 검사** — 위반 나오면 버전별로 나눠 볼 것 (v1 위반 519건은 의도적 방치)
- 컨테이너에 `ps`/`pgrep` 없음 — PID는 `/proc/*/cmdline` 스캔
- 미커밋 위험: `makemigrations`는 반드시 앱 이름 지정 (drift 이력 있음)
